# CloudDisk 模块架构与工作原理

## 一、整体架构概览

CloudDisk 采用**微服务 + 网关代理**架构，由 4 个独立进程和 3 个基础设施组件协同工作：

```
                         ┌──────────────────────┐
                         │      浏览器 (SPA)      │
                         └──────────┬───────────┘
                                    │ HTTP REST API
                                    │ :8888
                 ┌──────────────────▼──────────────────────┐
                 │              server  (HTTP 网关)          │
                 │          CloudDiskServer + wfrest         │
                 │                                          │
                 │  路由注册:                                │
                 │    GET  /              → index.html      │
                 │    POST /api/v1/auth/register            │
                 │    POST /api/v1/auth/login               │
                 │    GET  /api/v1/user/me                  │
                 │    GET  /api/v1/files                    │
                 │    POST /api/v1/files                    │
                 │    GET  /api/v1/file/{id}                │
                 └──┬────────────┬──────────────┬──────────┘
                    │ SRPC       │ SRPC         │ WFMySQLTask
          ┌─────────▼──┐  ┌──────▼──────┐  ┌───▼──────────┐
          │ userServer │  │ fileServer  │  │    MySQL      │
          │   :8001    │  │   :8002     │  │  CloudDisk DB │
          └─────┬──────┘  └──────┬──────┘  └──────────────┘
                │                │
                └───────┬────────┘
                        │ 注册 & 心跳
                ┌───────▼──────┐
                │    Consul    │
                │   :8500      │
                └──────────────┘

          ┌─────────────────────────────────────────┐
          │           异步云备份链路                   │
          │                                         │
          │  server ──publish──► RabbitMQ           │
          │                        │                │
          │                  oss_consumer ──► 阿里云 OSS
          └─────────────────────────────────────────┘
```

## 二、各模块详细设计

### 2.1 server — HTTP 网关

**入口文件**: `main/main.cc`
**监听端口**: 8888
**核心类**: `CloudDiskServer`（`include/CloudDiskServer.h`）

#### 设计模式：装饰器（Wrapper）

`CloudDiskServer` 组合了 `wfrest::HttpServer`，在其基础上封装路由注册和 SRPC 客户端获取：

```
CloudDiskServer
├── server_ (wfrest::HttpServer)       ← 组合，非继承
├── register_routes()                  ← 注册所有路由
├── start() / stop() / list_routes()   ← 代理给 server_
├── userSRPCClient()                   ← 静态方法，通过 Consul 发现 user-service
└── fileSRPCClient()                   ← 静态方法，通过 Consul 发现 file-service
```

#### 路由模块划分

| 方法 | 注册函数 | 路由 | 处理器 |
|------|----------|------|--------|
| `register_www_module()` | `server_.Static()` | `/`, `/static/*` | 静态文件服务 |
| `register_auth_module()` | `server_.POST()` | `/api/v1/auth/register` | `register_handler` |
| | | `/api/v1/auth/login` | `login_handler` |
| `register_user_module()` | `server_.GET()` | `/api/v1/user/me` | `user_handler` |
| `register_file_module()` | `server_.GET()` | `/api/v1/files` | `file_list_handler` |
| | `server_.POST()` | `/api/v1/files` | `file_upload_handler` |
| | `server_.GET()` | `/api/v1/file/{id}` | `file_download_handler` |

#### SRPC 客户端获取流程

```
CloudDiskServer::userSRPCClient()
  │
  ├─► ConsulManager::discoverService("user-service")
  │     └─► GET http://127.0.0.1:8500/v1/health/service/user-service?passing
  │           └─► 返回 {host, port}
  │
  └─► new userHandler::SRPCClient(host, port)
        └─► 返回静态客户端引用（单例复用）
```

### 2.2 userServer — 用户微服务

**入口文件**: `main/userServer_main.cc`
**监听端口**: 8001
**协议**: SRPC (Protobuf RPC over Sogou SRPC Framework)

#### 服务定义（`proto/userHandler.proto`）

```protobuf
service userHandler {
    rpc Register(RegisterRequest) returns (RegisterResponse);
    rpc Login(LoginRequest)       returns (LoginResponse);
    rpc UserInfo(UserInfoRequest) returns (UserInfoResponse);
}
```

#### 实现类：`userHandlerService`

注册到 SRPC 服务器，每个 RPC 方法内部使用 Workflow 的**异步任务图**：

```
client RPC 请求到达
  │
  └─► userHandlerService::Register(req, resp, ctx)
        │
        ├─ 1. 生成随机盐值 (CryptoUtil::generate_salt)
        ├─ 2. 哈希密码     (CryptoUtil::hash_password)
        ├─ 3. 创建 WFMySQLTask 异步执行 INSERT
        │     │
        │     └─► 回调: 检查 affected_rows == 1
        │            ├─ 成功 → resp.set_code(200), resp.set_user_id(...)
        │            └─ 失败 → resp.set_code(409), "用户已存在"
        │
        └─ 4. task 加入 ctx->get_series() 任务序列
```

#### 登录流程中的安全设计

```
Login 请求
  │
  └─► 防抖: 不在数据库层面验证密码
        │
        ├─ SELECT id, password, salt, created_at
        │    WHERE username = ?
        │
        ├─ salt + password → SHA-256 → 与 db_password 比对
        │
        └─ 一致 → 签发 JWT:
              Payload { id, username, created_at, exp: +3600s }
              签名密钥: "$Rv&O98@"
```

#### 服务生命周期

```
main()
  │
  ├─► SRPCServer server
  ├─► server.add_service(&userHandlerService)
  ├─► server.start(8001)
  │     │
  │     ├─► ConsulManager::registerService(
  │     │     "user-service-1", "user-service", "127.0.0.1", 8001)
  │     │     └─► Consul TTL Check: 10 秒
  │     │
  │     └─► ConsulManager::startHeartBeat("user-service-1")
  │           └─► 每 9 秒发送一次 servicePass（TTL 倒计时重置）
  │
  ├─► wait_group.wait()  ← 阻塞直到 SIGINT
  │
  └─► 清理:
        ConsulManager::deregisterService("user-service-1")
        server.stop()
```

### 2.3 fileServer — 文件微服务

**入口文件**: `main/fileServer_main.cc`
**监听端口**: 8002
**协议**: SRPC

#### 服务定义（`proto/fileHandler.proto`）

```protobuf
service fileHandler {
    rpc fileInfo(fileInfoRequest) returns (fileListResponse);
}
```

#### 核心逻辑

```
fileInfo(req.uid, resp)
  │
  └─► SELECT id, filename, size, created_at, last_update
        FROM tbl_file WHERE uid = ?
        │
        └─► 遍历结果集，填充 fileListResponse.files[]
              └─► resp.set_code(200)
```

#### 服务注册同 userServer

注册为 `file-service`，由 Consul 管理健康状态。

### 2.4 oss_consumer — OSS 异步消费者

**入口文件**: `main/OssWorker_main.cc`
**无监听端口**（纯 Worker 进程）

#### 工作原理

```
oss_consumer 启动
  │
  ├─► RabbitMQ::startConsumer()
  │     └─► channel.BasicConsume("oss.queue") → 获取 consumerTag
  │
  └─► 无限循环:
        │
        ├─► RabbitMQ::RabbitConsumer()
        │     └─► BasicConsumeMessage → Envelope { filename, path }
        │
        ├─► OSSManager::upload(filename, path)
        │     └─► OssClient::PutObject(bucket, filename, localPath)
        │
        ├─► 成功 → channel.BasicAck(envelope)    ← 确认消费
        └─► 失败 → 不 ACK，消息重回队列重试
```

#### 为什么用消息队列？

文件上传是**同步落盘 + 异步云备份**的二阶段操作：

```
用户上传请求
  │
  ├─► [同步] 本地 storage/ 落盘 + MySQL 写入元数据  ← 快速返回给用户
  │
  └─► [异步] RabbitMQ → oss_consumer → 阿里云 OSS  ← 后台慢慢上传
```

这样避免了阿里云 OSS 上传的延迟阻塞用户请求。

### 2.5 ConsulManager — 服务注册与发现

**文件**: `include/ConsulManager.h` + `src/ConsulManager.cc`

#### 单例模式

使用局部静态变量实现线程安全的单例（C++11 保证）。

#### 核心接口

| 方法 | 功能 |
|------|------|
| `registerService(id, name, ip, port)` | 向 Consul 注册服务，使用 TTL 健康检查（10 秒） |
| `servicePass(service_id)` | 向 Consul 报告健康（重置 TTL 倒计时） |
| `startHeartBeat(service_id)` | 启动自动心跳：先立即 `servicePass`，然后每 9 秒循环 |
| `discoverService(service_name)` | 查询 Consul 中健康的服务实例列表，返回第一个 |
| `deregisterService(service_id)` | 服务关闭时主动注销 |

#### 心跳机制

```
startHeartBeat("user-service-1")
  │
  ├─► servicePass(...)               ← 立即报一次（防刚注册就超时）
  │
  └─► WFTimerTask(9s)
        └─► timer_callback:
              ├─► servicePass(...)    ← 重置 Consul TTL 为 10s
              └─► 创建下一个 WFTimerTask(9s)  ← 9 < 10，确保不过期
                    └─► series_of(task)->push_back(next)
```

### 2.6 OSSManager — 阿里云 OSS 管理器

**文件**: `include/OssManager.h` + `src/OssManager.cc`

#### 初始化流程

```
OSSManager 构造函数（单例首次调用时执行）
  │
  ├─► 读取 config.json 获取 endpoint, accessKeyId, accessKeySecret, bucketName
  ├─► AlibabaCloud::OSS::InitializeSdk()
  └─► _client = make_unique<OssClient>(endpoint, accessKeyId, accessKeySecret, conf)
```

#### 上传/下载

```
upload(objectName, localPath)
  └─► _client->PutObject(bucketName, objectName, localPath)
        └─► 阿里云 OSS 服务端从本地路径读取

download(objectName, data)
  └─► _client->GetObject(bucketName, objectName)
        └─► 返回流 → stringstream → std::string
```

### 2.7 RabbitMQ — 消息队列

**文件**: `include/RabbitMQ.h` + `src/RabbitMQ.cc`

#### 单例初始化

```
RabbitMQ 构造函数
  ├─► URI: amqp://guest:guest@localhost:5672/%2f
  └─► _channel = Channel::CreateFromUri(uri)
```

#### 生产者（server 端）

```
RabbitProducer(filename, localPath)
  │
  ├─► 构造 JSON: {"filename": hashcode, "path": "storage/hashcode"}
  ├─► BasicMessage::Create(json_string)
  └─► channel.BasicPublish(exchange="oss.direct", routingKey="oss", message)
```

#### 消费者（oss_consumer 端）

```
startConsumer()
  └─► _consumerTag = channel.BasicConsume("oss.queue", noAck=false, ...)

RabbitConsumer()
  └─► channel.BasicConsumeMessage(consumerTag, envelope)
        └─► 阻塞等待消息，返回 Envelope

Ack(envelope)
  └─► channel.BasicAck(envelope)
```

### 2.8 CryptoUtil — 密码学工具

**文件**: `include/CryptoUtil.h` + `src/CryptoUtil.cc`

| 方法 | 算法 | 用途 |
|------|------|------|
| `generate_salt(length=8)` | 随机字符 (0-9a-zA-Z) | 生成密码盐值 |
| `hash_password(password, salt)` | SHA-256 (OpenSSL EVP) | 密码哈希 |
| `generate_hashcode(data, n)` | SHA-256 (OpenSSL EVP) | 文件内容哈希（去重 & 存储路径） |
| `generate_token(user)` | JWT HS256 | 生成认证 Token |
| `verify_token(token, user)` | JWT HS256 验证 | 验证 & 解析 Token |

#### JWT Token 结构

```
Header:  {"alg": "HS256", "typ": "JWT"}
Payload: {
    "sub": "LoginToken",
    "id": 用户ID,
    "username": "用户名",
    "created_at": "注册时间",
    "exp": 当前时间 + 3600秒
}
Signature: HMAC-SHA256(Header.Payload, "$Rv&O98@")
```

## 四、关键设计决策

### 4.1 为什么文件下载从 OSS 而非本地？

`src/FileHandler.cc` 的 `file_download_handler` 中，实际下载路径是 `OSSManager::download()`，注释掉的代码原本是读本地文件 `resp->File(STORAGE_DIR + "/" + hashcode)`。这种设计意味着：
- 文件以阿里云 OSS 为**唯一可靠存储源**
- 本地 `storage/` 仅作为上传中转
- `oss_consumer` 异步上传完成后，`oss_consumer` 并未删除本地文件（当前实现可优化）

### 4.2 为什么用户信息接口不查库？

`user_handler` 直接从 JWT Token 中解析用户信息，因为 `generate_token` 时已经把 `id`, `username`, `createdAt` 嵌入 Payload。这避免了额外的数据库查询，前提是 Token 在有效期内且未被篡改。

### 4.3 为什么注册/登录通过 SRPC 而非直接操作 MySQL？

HTTP 网关不再直接写 SQL——这意味着：
- 业务逻辑集中在微服务中，网关只做路由和鉴权
- 可以独立扩展 userServer 实例（Consul 做负载均衡）
- 数据库访问在微服务层统一管理
